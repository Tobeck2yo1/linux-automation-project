# Task 1: Automate Directory and File Creation

## Script

`scripts/create_structure.sh`

## Purpose

The purpose of this script is to automate the creation of nested directories and files while ensuring that the script can safely be executed multiple times.

The script uses commands such as:

- `mkdir -p`
- `touch`
- `echo`
- `date`
- `mktemp`
- `mv`

Before creating files, the script checks whether they already exist. This prevents important existing files from being overwritten.

The script also creates timestamped reports so that reports generated during different executions have unique names.

Example timestamp format:

`report_20261124_142530.txt`

## Idempotency

The script was designed to be idempotent.

This means executing the script multiple times does not cause unnecessary errors or overwrite existing configuration files.

For example:

```bash
if [[ -f "$file_path" ]]; then
    log_info "File already exists and was not overwritten."
else
    touch "$file_path"
fi
```

Directories are created using:

```bash
mkdir -p
```

The `-p` option allows existing directories to remain unchanged while creating missing directories.

## Execution

```bash
./scripts/create_structure.sh
```

A custom destination can also be passed as an argument:

```bash
./scripts/create_structure.sh "$HOME/automation-demo"
```

# Task 2: System Health Monitor

## Script

`scripts/health_monitor.sh`

## Purpose

This script monitors key Linux system resources and generates a timestamped health report.

The script captures information using standard Linux commands including:

- `df` for disk utilization
- `free` for memory utilization
- `ps` for process and CPU information
- `hostname` for system identification
- `uname` for kernel information
- `uptime` for system uptime

The collected values are stored in Bash variables and evaluated against configurable thresholds.

Default thresholds are:

- Disk usage: 80%
- Memory usage: 80%
- CPU usage: 80%

An example execution is:

```bash
./scripts/health_monitor.sh
```

Custom thresholds can also be supplied:

```bash
./scripts/health_monitor.sh 75 70 85
```

In this example:

- Disk threshold = 75%
- Memory threshold = 70%
- CPU threshold = 85%

## Conditional Checks

The script uses `if` statements to compare current resource utilization against the configured thresholds.

If the system resource usage reaches or exceeds the threshold, the script reports a warning.

Otherwise, it reports the resource as healthy.

## Exit Codes

The health monitor uses exit codes to communicate the result of execution.

- `0` indicates that all monitored resources passed the configured checks.
- `1` indicates that one or more resource thresholds were reached or exceeded.
- `130` can indicate that execution was interrupted using `Ctrl+C`.

The exit code can be checked using:

```bash
echo $?
```

# Task 3: Functions and Code Reuse

Repeated functionality was separated into named Bash functions.

The shared function library is located at:

`lib/common.sh`

It contains functions for:

- Information messages
- Success messages
- Warning messages
- Error messages
- Directory validation
- Numeric threshold validation

The main scripts load this library using:

```bash
source "$LIBRARY_FILE"
```

Functions use positional arguments such as:

```bash
$1
$2
```

They also use `local` variables to avoid unnecessary global variables.

Example:

```bash
validate_number() {
    local value="$1"
    local name="$2"

    if [[ ! "$value" =~ ^[0-9]+$ ]]; then
        log_error "$name must be a whole number."
        return 1
    fi
}
```

This approach makes the scripts easier to maintain, understand, and reuse.

# Task 4: Input Validation and Script Safety

Several defensive Bash scripting techniques were implemented.

The scripts use:

```bash
set -e
set -u
set -o pipefail
```

These options improve reliability by detecting unexpected command failures, undefined variables, and pipeline failures.

## Input Validation

The scripts validate user-provided values before processing them.

For example, system health thresholds must:

- Contain numeric values
- Be between 0 and 100

Directory paths are also checked before they are used.

This reduces the likelihood of invalid input causing unexpected behavior.

## Trap and Cleanup

The scripts use `trap` to respond to interruptions and perform cleanup operations.

For example:

```bash
trap cleanup EXIT
```

Interrupt signals such as `INT` and `TERM` are also handled.

This helps ensure that temporary files are removed and that scripts terminate in a controlled manner.
